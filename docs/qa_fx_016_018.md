## Corrections natives mises en évidence par les tests

- Reverb normalise le damping sous 64 et interprète Room size 0 comme 64 : les
  descripteurs d'édition utilisent les domaines effectifs.
- Les valeurs par défaut diffèrent entre Insert et System (Reverb 40 versus 80).
  `EffectMgr::add2XML` respecte maintenant le mode XML complet ; un copier/coller
  ne perd plus un paramètre omis parce qu'il était le défaut de la source.
- `EffectMgr::setTempoRatio` centralise les conversions, distingue Echo/Reverse,
  évite l'enroulement d'octet et restaure le rapport après init/preset/paste.
  Les anciennes formules divergentes des callbacks sont remplacées.
- `EffectMgr::init` préserve le preset chargé avant de reconstruire l’effet ;
  les relectures XIZ/session vérifient aussi un preset non nul (2).
- Après libération d'un effet, son pointeur est remis à null avant construction,
  afin qu'un échec d'allocation ne laisse pas un objet libéré comme effet actif.

## Synchronisation et limites conservées

L'adaptateur sérialise les accès aux propriétaires/allocateur avec un verrou
réentrant ; le renderer tente l'accès sans attendre. Les mutations et allocations
FX se font dans cette exclusion, pas depuis Compose. Les accès de lecture,
clipboard, chargement/sauvegarde et modules qui partagent cet allocateur utilisent
le même point de synchronisation ; l'installation PAD conserve son try-lock.

**Lorsqu'un accès d'édition occupe le moteur, le callback émet un bloc silencieux.**
Le compteur diagnostic `editorSkips` permet de le quantifier. Le test concurrent
vérifie l'exclusion et la progression, pas l'absence de coupure audible ni les
performances sur appareil. Ce compromis du prototype doit être mesuré au lot 021,
notamment pour changements de type/preset, snapshots Formant et previews de filtre.
Il ne constitue pas une qualification audio sans glitch.

La courbe EQ garde la dernière réponse native pendant le drag ; le marqueur et
les knobs suivent la valeur locale, et la réponse est recalculée au relâchement.
La preview Dynamic Filter est statique et bornée, pas une animation du LFO.
Les rapports au tempo restent bornés par les délais/fréquences codables du fork.

Aucune installation, écoute comparative ou QA visuelle/accessibilité sur appareil,
aucun commit/push/publication. Ajustements du prototype sur pièce, routages 019,
persistance transverse 020 et campagne finale 021 restent à faire. Ne pas déclarer
ces validations différées réussies.

## Ajustement du 15 novembre 2026 — slot unique et knobs

À la demande de Mick, les onglets FX 1/2/3 (ou 4/8 selon scope) sont supprimés
de l'éditeur : seul le slot ouvert depuis la liste est édité, avec son contexte
et le retour vers la liste. Type et Preset utilisent les mêmes knobs et popups
sur appui long que les autres enums. Pendant leur glissement, le choix affiché
reste local ; le moteur change de type/preset au relâchement, avec une seule
réconciliation. Revenir au choix initial ne réapplique pas son preset.
Le menu d'actions reste distinct des contrôles de paramètres.

Validation de cette itération : 38 tests JVM réussis ; APK debug et AndroidTest
compilés. Scénario Compose adapté au slot unique et à l’appui long sur Type,
compilé mais non exécuté sur appareil. Aucune installation.

Ajustement du bandeau FX : le titre générique FX est remplacé par Insert N,
Master N (System) ou Part N (numéro de slot, propriétaire complet dans le fil
de contexte). Retour « ‹ FX ». Le message des Inserts sans entrée indique
explicitement qu’aucune source audio ne leur est affectée ; les assignations
restent à implémenter au lot 019. APK debug compilé.

## Source des Inserts — 15 novembre 2026

Knob Source dans Routing, présent aussi sur un slot Off : Off / Master /
Part 1..16, popup existant sur appui long. Affichage 0=Off, 1=Master, 2..17=Parts
1..16 ; le propriétaire Master conserve son codage natif -1/-2/0..15.
L'écriture passe par Master::setInsertionFxSource ; aucune assignation dans Part
ou System. Le geste garde son choix local jusqu'au commit comme Type/Preset.

Contrat natif réussi : bornes, indices affichés/natifs, isolation du slot voisin,
source non copiée par paste et conservée à la relecture de session. 38 tests JVM,
APK debug et AndroidTest compilés ; pas d'installation ou d'écoute sur appareil.
Le lot 019 conserve les routages Part et System restants.

Restore current preset réapplique les paramètres de l'effet depuis son preset
courant, sans modifier source ni bypass. Clear audio memory appelle cleanup :
il vide les buffers DSP (queues de réverbération, échos, etc.) tout en gardant
les réglages ; une entrée toujours jouée alimente de nouveau l'effet.

Actions FX désormais directement dans le bandeau, dans l'ordre R / E / C / P :
R rouge rétablit le preset courant, E vide les mémoires audio. Le menu ⋮ est
retiré. R/E sont désactivés pour un slot Off ; les opérations natives restent
celles déjà testées. Depuis Filter, R/E concernent toujours l'effet propriétaire.

## Recherche EQ upstream et regroupement des Inserts

Comparaison effectuée le 15 novembre 2026 avec
https://raw.githubusercontent.com/zynaddsubfx/zynaddsubfx/master/src/Effects/EQ.cpp
(fichier récupéré dans /tmp, sans modifier le fork) : le code upstream conserve
les deux presets `{67}` et les mêmes valeurs de bande `{0,64,64,64,0}`.
EQ::setpreset réapplique ces valeurs aux 128 indices ; les deux choix ramènent
donc au même EQ neutre, sans courbe musicale distincte. Aucune intention de
différenciation n'est documentée dans les sources consultées.

L'interface FLTK vendored make_eq_window ne présente pas de sélecteur Preset,
contrairement à make_dynamicfilter_window qui suit. La documentation officielle
https://zynaddsubfx.sourceforge.io/Doc/ (section Equalizer, extrait de recherche)
décrit le gain et les bandes mais pas de catalogue de presets EQ. L'accès direct
à la documentation a renvoyé 403 ; le code upstream a été lu directement.

À la demande de Mick, Routing et Mix sont réunis en une seule section
Routing / Mix pour les Inserts (Source, Dry/Wet et Pan selon l'effet).
Les descripteurs et propriétaires natifs restent distincts ; seul le regroupement
Compose change. APK debug compilé, pas de nouvelle qualification appareil.
